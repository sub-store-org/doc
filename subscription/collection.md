# 组合订阅

组合订阅（collection）把多条单条订阅**合并为一条输出**，适合把多个机场/订阅源合并成一个链接，分发给多个客户端使用。

## 基本用法

1. 在「订阅」页新建一个**组合订阅**
2. 在组合订阅里添加若干条**单条订阅**（通过名称引用，支持同时引用本地+远程内容）
3. 保存后可获得组合订阅的输出链接，导入客户端即可同时获得所有订阅的节点

特点：

- 组合订阅的**合并顺序**由 `mergeSources` 参数控制：`localFirst`（本地优先）/ `remoteFirst`（远程优先）
- 组合订阅里的各条单条订阅仍然可以保留各自的处理操作（筛选、脚本等）
- 支持对组合订阅整体再做处理操作

## 失败处理

远程订阅可能失败，可通过 `ignoreFailedRemoteSub` 参数控制失败行为：

| 值 | 行为 |
| --- | --- |
| `disabled` | 严格报错：订阅处理出错时立即报错并通知 |
| `enabled` | 失败通知：远程订阅失败时跳过失败项并通知；其他错误仍报错 |
| `quiet` | 失败静默：远程订阅失败时跳过失败项且不通知 |
| `fallbackNotify` | 兜底通知：任何错误时不报错，返回空结果并通知 |
| `fallbackQuiet` | 兜底静默：任何错误时不报错，静默返回空结果 |

前端编辑页也有对应的「忽略失败的远程订阅」开关。

## 客户端拉取超时的应对

有的客户端拉取订阅会超时且无法设置，此时可以：

1. 在组合订阅里打开**忽略失败的远程订阅**，避免单条订阅超时导致整体超时
2. 将超时设为 3000–4000ms
3. 或配置**同步到 Gist**，让客户端使用 Gist 链接（同步任务不存在超时问题）
